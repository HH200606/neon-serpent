## 1. 背景与问题

### 1.1 立项假设

> **H0**：愿意在碎片时间玩一局的人，找不到「打开即玩、手感扎实、手机能玩」的贪吃蛇；多数复刻能跑，但手感与进入成本都被妥协。

H0 是**假设，尚未验证**（见 1.3 的观测计划）。它成立与否直接决定差异化定位是否有效，因此列为**投资前的第一个门**。

### 1.2 三个可验证子问题

| ID | 子问题 | 观察方式 | 现状 |
| :--- | :--- | :--- | :--- |
| P1 | 移动按格跳，速度一快像瞬移 | 逐帧录屏，看蛇头位移是否连续 | 待观测 |
| P2 | 难度只靠加速，20 秒后只剩焦虑 | 死亡时间分布 | 待观测（无埋点） |
| P3 | 手机不可玩或误触严重 | 真机试玩 + 误触计数 | 待观测 |

### 1.3 竞品观测计划（H0 的验证方法）

抽样 5 个公开可玩的同类（搜索"贪吃蛇 在线"前 5 个可玩页面），按下表逐项实测。**这张表必须先填完，才允许继续投入 V2 功能。**

| 观测项 | 测量方法 | 通过标准 |
| :--- | :--- | :--- |
| 首次可玩时间 | 硬刷新到可操作，秒表 3 次取中位 | ≤1.5s 视为合格 |
| 移动连续性 | 30fps 录屏逐帧看蛇头位移 | 有插值=连续；整格跳=不合格 |
| 移动端可玩 | 375px 视口实际操作 | 有滑动或虚拟键=可玩 |
| 音效 | 吃果实/死亡是否有反馈 | 两者都有=合格 |
| 首屏体积 | DevTools Network，禁用缓存 | ≤100KB |
| 广告/登录阻断 | 打开后是否要求登录或遮挡 | 无阻断=合格 |

**判定门**：若 5 个样本中 ≥3 个在上述 ≥4 项合格，则 H0 不成立——差异化理由需重新论证，应停止扩功能、只做已有体验的维护。

### 1.4 设计立场

不做玩法创新，把预算全部投入**手感、节奏、进入成本**；不用任何图片与音频素材；保持零依赖、无构建。

## 2. 目标与非目标

### 2.1 目标

| ID | 目标 | 衡量（对应指标） |
| :--- | :--- | :--- |
| G1 | 打开即可玩，3 秒内进入第一局 | M-2 开局率、M-9 首屏时间 |
| G2 | 手感成立：不跳格、转向跟手、死亡有反馈 | M-6 掉帧率、M-10 输入延迟 |
| G3 | 一局有"还想再来"的张力 | M-1 再来一局率、M-3 单局时长 |
| G4 | 手机上真的能玩 | M-7 误触率 |

### 2.2 非目标

| 非目标 | 理由 | 决策 |
| :--- | :--- | :--- |
| 账号 / 云存档 | 一局 1–2 分钟，登录是纯流失点 | ADR-3 |
| 排行榜 / 多人 | 用户量不足以支撑榜单有效性，且会破坏自洽难度 | ADR-4 |
| 内购 / 广告 | 定位是开源作品集与公共小游戏 | ADR-1 |
| 关卡编辑器 / 皮肤 | 引入状态管理复杂度，收益与一期目标不符 | — |
| 玩法大改（地形、传送门） | 违背"零学习成本"前提 | ADR-2 |

## 3. 用户

### 3.1 用户假设（未经验证）

| 画像 | 特征 | 关键需求 | 场景 |
| :--- | :--- | :--- | :--- |
| A 碎片时间玩家 | 通勤、排队、会前 5 分钟 | 立刻能玩、一局能结束、不耗流量 | 手机浏览器、社交链接 |
| B 霓虹美学爱好者 | 喜欢 CRT / 赛博朋克 | 视觉统一、有质感 | 设计社区、分享图 |
| C 前端同行 | 会看源码 | 代码干净、取舍可读 | GitHub、技术社区 |
| D 演示用户 | 想录屏、发朋友圈 | 有自动演示、画面好看 | `?demo=1` |

**这四条是假设**，不是研究结论。验证计划：找 5 位目标用户（≥3 位非技术背景）各做一次 5 分钟可用性测试，问四件事——最近一次玩小游戏是什么时候、打开一个陌生游戏最先看什么、玩到第几局会想关掉、会不会分享。样本带到 v1.2 修订。

### 3.2 用户旅程（JTBD）

> 当我手上有 2 分钟空档时，我想立刻玩一局有点挑战、输了还想再来一次的小游戏，这样我能把这段碎片时间填得舒服。

必须避免的失败路径：打开要等资源 → 首次转向没反应或反向自杀 → 手机上滑一下整页跟着滚 → 死了不知道为什么。

## 4. 指标

### 4.1 指标定义与决策规则

| ID | 指标 | 定义 / 口径 | 数据来源 | 目标 | 止损线 | 观测窗口 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| M-1 | 再来一局率（北极星） | 结算后 10s 内再次开局 ÷ 完成一局 | `run_end`→`run_start` | ≥30% | <20% 连续两轮迭代 | 2 周 |
| M-2 | 开局率 | 进入 playing ÷ 打开页面 | `page_view`,`run_start` | ≥65% | <45% | 1 周 |
| M-3 | 单局时长中位数 | playing→结算，**不含暂停** | `run_start`,`run_end` | 45–120s | >180s 或 <25s | 1 周 |
| M-4 | 分数中位数 | 结算分数，分首局/回访两档 | `run_end.score` | 首局 60–150 | 首局 >300 或 <30 | 2 周 |
| M-5 | 连击达成率 | 达到过 ≥×3 的玩家占比 | `fruit_eaten.combo` | ≥25% | <10% | 2 周 |
| M-6 | 掉帧率 | 帧时长 >16.7ms 的帧占比 | `frame_stats` | ≤5% | >15% | 每版本 |
| M-7 | 手机误触率 | 同局内无效滑动 ÷ 总滑动 | `swipe(ignored)` | ≤5% | >12% | 2 周 |
| M-8 | 回访代理 | 同设备 24h 内 ≥2 次开局占比（无身份，仅近似） | 本地序号 vs 时间 | ≥20% | <8% | 2 周 |
| M-9 | 首屏可交互 | 导航开始→可开始游戏 | `performance` 实测 | 4G ≤600ms / 本地 ≤150ms | 超 2 倍 | 每版本 |
| M-10 | 输入延迟 | keydown 到方向生效 | 手测 10 次 + 帧计数 | ≤1 帧 | >3 帧 | 每版本 |

**观测项（不设目标值，仅用于诊断）**：死亡归因分布（撞墙/自咬）。把撞墙率当 KPI 会诱导"让自咬更容易"的错误调优。

### 4.2 决策规则

| 条件 | 动作 |
| :--- | :--- |
| M-1 ≥30% 且 M-4 在区间 | 进入 V2（每日挑战），扩功能 |
| M-1 20–30% | 只调参（旋钮见 7.3），不扩功能 |
| M-1 <20% 连续两轮 | 停止投入；冻结功能，仅修缺陷 |
| M-6 >15% | 触发性能专项，优先于任何新功能 |
| M-7 >12% | 重做移动端输入方案，冻结其它改动 |

### 4.3 指标口径原则

不看 PV；分数不是越高越好；护栏指标优先于增长指标；**没有埋点的指标一律标注"未观测"，不得写进结论**。

### 7.2 难度指标

| 指标 | 目标带 | 说明 |
| :--- | :--- | :--- |
| 死亡时间分布 | 40% 落在 30–60s，≤10% 在 <15s | 太早死=挫败，太晚死=无聊 |

### 7.3 调参旋钮（症状 → 参数）

| 症状 | 首选参数 | 调整方向 |
| :--- | :--- | :--- |
| 玩家 15s 内大量死亡 | baseStep 150→165 | 放慢起手 |
| 30s 后仍不紧张 | speedUp 0.978→0.973 | 加快爬坡 |
| 连击几乎没人达成 | comboWindow 2600→3200 | 放宽窗口 |
| 分数普遍过高 | comboMax 5→4 | 压低上限 |
| 金果实没人去吃 | bonusLife 9000→12000 | 延长存在 |

### 7.4 死亡与反馈

死亡瞬间：粒子 26 颗 + 抖动 12px + 音效下滑；结算显示本局/最高分与重开入口。一局一命，无复活（ADR-5）。

## 10. 视觉与音频

### 10.1 视觉

| 项 | 规范 |
| :--- | :--- |

### 10.2 音频（全部合成）

| 事件 | 波形 | 频率 | 时长 | 单音 gain |
| :--- | :--- | :--- | :--- | :--- |
| 开始 | triangle | 380→620Hz | 0.16s | 0.18 |
| 吃果实 | square | 520→760Hz | 0.10s | 0.14 |
| 金果实 | triangle ×3 | 660/880/1180Hz | 0.09–0.12s | 0.13 |
| 死亡 | sawtooth | 240→55Hz | 0.42s | 0.20 |

峰值 ≤-12 dBFS（NFR-6）：所有音效先经 `DynamicsCompressor`（threshold -12dB、ratio 20）限幅再进扬声器；暂停时挂起（FR-6.3）。静音状态被持久化时，HUD 显示「音效已关闭」文字提示，被浏览器拦截自动播放时显示「点一下开启音效」并补播被拦下的那次音效——声音问题不再只能靠猜。

## 18. 附录

### 18.1 术语

| 术语 | 释义 |
| :--- | :--- |
| 固定步长 | 逻辑按固定时间片推进，与渲染帧率解耦 |
| 渲染插值 | 用累加器余量在格子间平滑绘制，避免跳格 |
| 连击窗口 | 连续吃果实仍累计倍率的时间容忍度 |
| 掉帧率 | 帧时长 >16.7ms 的帧占比 |
| DPR | 设备像素比，决定画布后备分辨率 |

### 18.2 公式复核

- 步长：`step(n) = max(76, 150 × 0.978^n)`，n 为已吃普通果实数
- 得分：`score += base × min(5, combo)`
- 典型单局（45–120 秒）得分参考区间：100–400
